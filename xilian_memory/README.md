# xilian_memory · 昔涟的回忆匣

参考开源插件 [astrbot_plugin_memos_integrator](https://github.com/zz6zz666/astrbot_plugin_memos_integrator)
的思路，为昔涟重写的一版长期记忆。

原版把记忆交给 **MemOS 云端服务**——要 API key、要联网、要开一个 Web 后台。
这一版把整套记忆搬回本机：**不联网、不花钱、数据不出门**，形状还是原版那个形状。

---

## 它做四件事

| | 说明 |
| --- | --- |
| **自动记录** | 每轮对话落地：谁、在哪个会话、说了什么、她答了什么（`turns` 表） |
| **她来提炼** | 她在回复末尾悄悄写一行 `[Remember: 类型\|内容]`，插件收走、存下、**抹掉**，用户看不见 |
| **记忆注入** | 下一轮之前，按当前话题把相关的旧事翻出来，附在 system prompt 末尾 |
| **四问协议** | 记忆能不能用，照「来源真值 / 主语归因 / 强相关 / 时效」逐条判 |

对应原版的四块：自动记忆管理、记忆注入、记忆安全协议、用户画像与手动指令。

---

## 相对原版改了四处

1. **记忆按 QQ 号硬隔离**——老公的旧事不会漏给伙伴，伙伴之间也互不相通。
   （原版靠 user_id 隔离，这里把身份也绑进来，和 `xilian_identity` 对齐。）
2. **检索不依赖 embedding**——本机没有向量模型，改用「字符二元组重合 + 短词整串包含
   + 时间衰减 + 重要度」打分，纯离线、可复现。
3. **口吻按她自己的性子来**——不是冷冰冰的「记忆库」，是她自己的「回忆匣」。
4. **「加反馈」变成「更正」**——主人可以纠正她记错的事，更正会随记忆一起被想起来。

## 指令

```
/回忆                     看自己的匣子（条数 + 最近三条）
/回忆 <关键词>            在自己的旧事里找（找不着时会回看最近的对话流水）
/回忆 更正 <一句短话>     纠正人家记错的事
/回忆 忘掉 <关键词>       把有关的旧事收起来
/回忆 用法                完整用法
```

管理员（`admins_id`）另有：

```
/回忆 <QQ号>              看那个人的匣子概览
/回忆 画像 [QQ]           画像：条数、类型分布、重要度、常提到的话题（本机统计，没问过模型）
/回忆 清单 [QQ] [N]       列出记忆，带编号
/回忆 检索 <QQ> <关键词>  跨人检索
/回忆 删除 <编号>         收掉某一条（软删，不真删）
/回忆 忘掉 <QQ> <关键词>  收掉某人的一批
/回忆 清空 [QQ]           清掉某人的；不带 QQ 就是全部
/回忆 统计                全局统计
```

非管理员问管理员专属的内容，她只会回一句「这个呀…人家不对外说啦。」

## 那行记忆长什么样

```
[Remember: 偏好|他喜欢在深夜写代码]
[Remember: 事件|5|他昨晚三点还在修 NapCat]
```

- 类型：`事实` / `偏好` / `事件` / `约定` / `关系`，不认识就归到「事实」；
- 中间那个数字是重要度 1~5（可省，默认 3）；
- 一轮最多收三条，内容一样的算同一条（只刷新时间，不重复堆）；
- **不要求独占一行**——写成「晚安♪[Remember: …]」也能摘干净。

那一行在发给用户之前被抹掉；万一被用户问起，她只会说「人家记得的，都是该记得的」。

## 数据

```
AstrBot/data/plugin_data/xilian_memory/memories.db
```

SQLite，三张表：

| 表 | 存什么 |
| --- | --- |
| `memories` | 记忆本体（类型 / 内容 / 重要度 / 来源 / 被想起次数 / 软删标记） |
| `turns` | 对话流水，默认留 4000 条 / 60 天，超了自动清 |
| `notes` | 更正 |

单个人的记忆上限默认 2000 条，超了把最旧的收起来。

---

## 可调项（`main.py` 顶部）

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `ENABLE` | `True` | 总闸。`False` 时插件完全不介入 |
| `MASTER_ID` | `3614298015` | 老公本人的 QQ 号 |
| `RECALL_LIMIT` / `RECALL_LIMIT_MASTER` | `5` / `8` | 一次注入几条旧事 |
| `MAX_PER_USER` | `2000` | 单个人最多留多少条记忆 |
| `KEEP_TURNS` / `TURNS_MAX_AGE_DAYS` | `4000` / `60` | 流水保留量 |

## 已知限制

1. **能不能记起来，一半看模型肯不肯写那一行。** 昔涟的人格稿很长，可能把这句指令压过去，
   那样记忆就不会增长。插件这边能保证的是：写了一定收得下、摘得干净。
2. **检索是词面匹配，不懂同义。** 「写代码」搜不到「敲键盘」。要语义检索得引入向量模型，
   这一步刻意没做（要保持离线）。
3. **群里共用一段历史。** AstrBot 的会话历史是共享的，插件管得住「谁的记忆给谁看」，
   管不住语气上的惯性。
4. **不支持流式输出的平台可能漏那一行。** 那一行是在回复完成后才摘的；QQ 不走流式，
   看不到这个问题。
5. **软删不占地方但不能回收。** `/回忆 删除` 只是把 `active` 置 0，方便反悔；
   真要瘦身就直接删 `memories.db`。
