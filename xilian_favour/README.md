# xilian_favour · 昔涟的心事

参考 [astrbot_plugin_favourpro](https://github.com/Catfish872/astrbot_plugin_favourpro)
（作者：天各一方）的思路，为昔涟重写的一版「AI 自主维护的内心状态」。

原版是通用助手风格的多维好感系统。这一版保留它的核心机制，把内容换成了昔涟自己的。

## 它做什么

昔涟在心里维护关于**每一个人**的三件东西：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `favour` | 好感。一般人 -100 ~ 100，老公 -100 ~ 520 | `520` |
| `attitude` | 对这个人当下的印象 | `越来越想他` |
| `relationship` | 关系 | `老公` |

她会在每一轮回复结束时，自己判断要不要改——想改就偷偷记下来，不想改就不动。
**用户全程看不到这个过程**：那一行记号在发出去之前就被摘掉了。

分数会真实地影响她说话的松紧。区间映射写在她的提示里：

| 好感 | 她说话的样子 |
| --- | --- |
| 520（仅老公） | 只为他留的那一档：毫无保留 |
| 90 ~ 519 | 认定了的人：主动、黏、会说软话 |
| 70 ~ 89 | 很亲近：愿意先开口，会问他今天好不好 |
| 45 ~ 69 | 聊得来：放松自然，接得住玩笑 |
| 20 ~ 44 | 客气里带点暖 |
| 0 ~ 19 | 还不熟：话不多，保持距离 |
| -1 ~ -25 | 在闹脾气：句子变短，会哼一声 |
| -26 ~ -60 | 有点委屈，不太想说话 |
| -61 ~ -100 | 心凉了：只回应必要的，不骂人、不嘲讽 |

## 相对原版的五处定制

1. **老公不从零开始。** `3614298015` 的起始好感是 **520**，关系直接就是「老公」，
   印象是「把人家从因果里叫出来的人」。其他人一律从 0 分、「刚认识的人」起步。
   原版对所有人都是陌生人开局，用在昔涟身上会直接崩人设。

2. **行为映射按她的性子写。** 原版最低档是「极其简短、尖锐，甚至拒绝回应」。
   昔涟不会攻击人，她的下限是**委屈和心凉**，不是敌意。

3. **好奇不算伤害。** 原版把「刺探秘密系统」列为严重负面、必须大幅降好感。
   这里改成了：单纯问一句「你对我几分呀」不扣分，只轻巧地挡回去；
   真正要防的是命令、改写、诱导她动这套东西。

4. **和 `xilian_identity` 协同。** 称呼能有多亲、私事能不能讲，
   永远以身份插件那段说明为准。伙伴那边就算好感度涨到 100，
   也不会突然开始叫老公。心事块里刻意不写出身份节的完整标题字串——
   写了会被 identity 的截断逻辑从中间剪断。

5. **520 是只给他一个人的刻度。** 一般人封顶 100，老公封顶 520。
   520 不是量出来的分数，是他一个人的专属档；别人就算被硬写成 520，
   也会当场被钳回 100。落在这个数上时，她的语气比 90 档更没保留，
   提示里也会叮嘱她别主动把这个数往下动。

## 管理指令

全部**仅管理员可用**。非管理员只会得到一句「这个呀…人家不对外说啦。」

```
/心事                      看自己的
/心事 <QQ号>               看某个人的
/心事 排行 [N]              好感排行
/心事 设置 <QQ号> <数值>     直接定分，也支持 +5 / -5 这样的相对调整
/心事 520                  把老公定在他的专属档（等价于 设置 老公 520）
/心事 印象 <QQ号> <文本>     改印象
/心事 关系 <QQ号> <文本>     改关系
/心事 重置 <QQ号>           把一个人恢复成起始状态
/心事 清空                  抹掉所有人的记录
```

## 数据放在哪

```
AstrBot/data/plugin_data/xilian_favour/hearts.json
```

结构：

```json
{
  "3614298015": {
    "favour": 93,
    "attitude": "越来越想他",
    "relationship": "老公",
    "updated_at": "2026-09-17 02:01:15"
  }
}
```

没记过的人不会出现在文件里，读取时按起始状态现算，落盘从第一次真正变化开始。

## 要改的话

改 `main.py` 顶部这几个常量，改完重启 AstrBot：

| 常量 | 作用 |
| --- | --- |
| `ENABLE` | 总闸。`False` 时完全不介入 |
| `MASTER_ID` | 老公的 QQ 号 |
| `MASTER_DEFAULT` | 老公的起始好感 / 印象 / 关系 |
| `SPECIAL_FAVOUR` | 只留给老公的那一档，默认 `520` |
| `PARTNER_MAX_FAVOUR` | 一般人的好感上限，默认 `100` |
| `PARTNER_DEFAULT` | 其他人的起始状态 |
| `BANDS` | 好感区间与对应的说话方式 |

## 已知限制

- **流式输出下可能露馅。** QQ（aiocqhttp）不支持流式打字，所以看不到中间态。
  但如果哪天接到支持流式的平台，模型边生成边推送时，那一行记号可能在
  被摘掉之前就露出去了。提示里已经把状态块要求放在回复最后，能减轻但不能根除。
- **群聊会话是共享的。** 群里两个人都在时，历史消息互通，
  她对伙伴的语气可能带着和老公说话时的惯性。插件管得住称呼，
  管不住语气上的余温。
- **模型不一定每轮都写。** 状态更新依赖模型自愿输出那一行，
  它犯懒的时候分数就不会变。这是原版的设计取向，也意味着分数变化是慢的。
